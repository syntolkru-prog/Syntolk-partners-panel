# Запуск локальной партнёрской программы Syntolk

Ниже находится готовый промпт. Его можно целиком отправить любой модели, у которой есть доступ к терминалу и браузеру на этом компьютере.

## Готовый промпт

```text
Запусти полностью локальную партнёрскую программу Syntolk на этом компьютере и открой одновременно кабинет администратора и кабинет партнёра.

Проект находится здесь:
C:\Users\fxcom\Documents\Codex\Syntolk-partners-panel

Работай самостоятельно до полностью открытых и проверенных кабинетов. Не удаляй, не пересоздавай и не очищай рабочую базу данных. Не запускай миграции с откатом. Не выводи ключ OpenRouter и другие посторонние секреты.

Выполни строго по порядку:

1. Проверь Docker командой `docker info`.
   - Если Docker Engine недоступен, запусти установленный Docker Desktop:
     `C:\Program Files\Docker\Docker\Docker Desktop.exe`
   - Запускай фоновое приложение скрытым окном и дождись, пока `docker info` начнёт успешно отвечать.

2. Проверь существующий контейнер `openpartner-postgres`.
   - Если он остановлен, выполни `docker start openpartner-postgres`.
   - Не создавай новый контейнер, если существующий найден.
   - Дождись состояния `running|healthy`.
   - Проверь, что рабочий PostgreSQL доступен на локальном порту 5433.

3. Перейди в папку проекта. Если папка `node_modules` уже существует, не переустанавливай зависимости без необходимости.

4. Собери текущий код:
   - `pnpm --filter @openpartner/api build`
   - `pnpm --filter @openpartner/router build`
   - `pnpm --filter @openpartner/portal build`

5. Проверь порты 4601, 4701 и 5673.
   - Если на порту уже работает нужный компонент именно из этого проекта и его проверка успешна, используй его.
   - Не завершай посторонние процессы.
   - Если компонент не запущен, запусти его скрытым фоновым процессом с отдельными файлами stdout/stderr в папке `outputs`:
     - API: `node apps/api/dist/server.js` из корня проекта;
     - счётчик переходов: `node apps/router/dist/server.js` из корня проекта;
     - портал: `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5673 --strictPort` из папки `apps/portal` (используй локальный `apps/portal/node_modules/vite/bin/vite.js`).
   - На Windows при `Start-Process` обязательно используй `-WindowStyle Hidden`.

6. Не считай один `/health` достаточной проверкой. Проверь:
   - `http://127.0.0.1:4601/health` → HTTP 200;
   - `http://127.0.0.1:4701/health` → HTTP 200;
   - `http://127.0.0.1:4601/install/status` → HTTP 200 и `needsSetup: false`;
   - `http://127.0.0.1:5673/login` → HTTP 200.
   Если `/health` работает, а `/install/status`, `/branding` или `/auth/whoami` возвращает 500/internal_error, сначала восстанови подключение PostgreSQL. Не создавай новые ключи до исправления базы.

7. Получи ключ администратора только из строки `ADMIN_API_KEY` локального файла `.env`. Не показывай и не изменяй остальные секреты. Проверь ключ запросом `GET /auth/whoami`: ожидаемая роль — `admin`.

8. Найди через администраторский API действующего партнёра с именем `Локальный партнёр Syntolk`. Если действующего ключа входа партнёра нет или он не проходит `GET /auth/whoami`, создай новый через:
   `POST /partners/<partnerId>/api-keys`
   с администраторской авторизацией и понятной локальной меткой. Это должен быть партнёрский ключ входа, а не ключ из раздела «Интеграция с CRM». Проверь, что `/auth/whoami` возвращает роль `partner` и правильный `partnerId`.

9. Открой две независимые браузерные сессии на разных origin, чтобы авторизации не перезаписывали друг друга:
   - администратор: `http://localhost:5673/login`;
   - партнёр: `http://127.0.0.1:5673/login`.

10. В каждой форме выбери «Ключ администратора / партнёра»:
    - войди администраторским ключом через `localhost`;
    - войди ключом `Локального партнёра Syntolk` через `127.0.0.1`.

11. Визуально проверь результат:
    - в админском кабинете должны быть пункты «Партнёры», «Программы», «Калькулятор», «ИИ-куратор», «Тестовые платежи»;
    - в партнёрском кабинете должно отображаться имя `Локальный партнёр Syntolk` и пункты «Калькулятор», «Календарь работ», «Результаты», «Ссылки», «Чат с куратором», «Комиссии», «Выплаты».

12. Оставь Docker, PostgreSQL, API, router и portal работающими. Оставь обе вкладки открытыми. В итоговом ответе сообщи статусы всех компонентов, две ссылки и имя вошедшего партнёра. Если что-то не получилось, не говори, что программа запущена: укажи конкретный неработающий компонент и исправляй до результата.
```

## Адреса после запуска

- Администратор: <http://localhost:5673/>
- Партнёр: <http://127.0.0.1:5673/>
- API: <http://127.0.0.1:4601/health>
- Счётчик переходов: <http://127.0.0.1:4701/health>

Разные написания `localhost` и `127.0.0.1` используются намеренно: браузер хранит для них независимые данные входа, поэтому администратор и партнёр могут быть открыты одновременно.
