# Syntolk: отчёт реализации ИИ-куратора

> Актуальное состояние на 13.10.2026: см. [повторный аудит всех 69 критериев](SYNTOLK_COACH_REAUDIT_20261013.md). OpenRouter уже проверен настоящими синтетическими запросами и включён; утверждения ниже о том, что были только mocks/template, описывают предыдущий этап от 12 октября.

12.10.2026. Ветка `feature/openpartner-full-copy`. Работа сделана поверх существующей незакоммиченной версии; чужие изменения и исходный калькулятор сохранены. Commit/push в рамках этой реализации не выполнялись.

## Результат и граница готовности

Установлен первый локальный вертикальный этап: отдельная вкладка партнёра и админа, анкета/цель/время/каналы, шаблонный план и принятие, задания и их версии, реальные собственные ссылки через общий link-service, самоотчёт и ручная проверка, постоянный чат, read-only показатели по партнёру/ссылкам, недельный разбор по запросу, явные снимки исходного калькулятора, очередь с worker/lease/cancel, in-app уведомления, takeover и журнал. Подготовлены OpenAI и OpenRouter adapters; оба тестировались только с mock-ответами.

По последнему выбору владельца используется **template**, а планировщик напоминаний выключен. Это не полноценный интеллектуальный менеджер, работающий с живой моделью. Всё ТЗ не объявляется выполненным; ниже явно обозначены непроверенные или отсутствующие части.

## Зафиксированные проверки

1. До миграций сделаны source ZIP и проверенная JSON/SQL-копия 15 core-таблиц, 13 строк. Исправлена первоначальная ошибка выбора tenant: использован `DEFAULT_TENANT_ID`, а не slug `default`; пустой первый артефакт не считается backup.
2. Создана отдельная БД `syntolk_coach_test_20261012`, применены миграции. Guard отвергает рабочее имя и совпадающую identity URL даже при других credentials. Рабочая БД не очищалась тестами.
3. Добавлены 11 таблиц куратора с tenant RLS и составными FK owner/tenant. В тесте непривилегированная роль не видит другого tenant; чужая связь task/link отвергается БД.
4. В интеграционном цикле пройдены анкета → план → повторное принятие → одна Link/placement → submission → review → ручное решение. Повтор не создаёт дублей. Финансовые действия отсутствуют.
5. Проверены stale version, чужие IDs, отсутствие grant, revoke, ended program, пауза, takeover, квоты, отсутствие ключа/согласия, отмена, восстановление lease двумя worker и окончательное освобождение зависшей проверки. OpenRouter/OpenAI network полностью mock.
6. В браузере на существующем тестовом партнёре `01M4RDV4BW7XB36ZG59N68H66N` создан профиль, принят план 3 × 30 минут, создана ссылка `st-01m4rk55c97wp6991rmeqh73rz`.
7. Ссылка открыта **настоящим браузером**: router перенаправил на `syntolk.ru/?cref=…`, клиентская регистрационная ссылка на странице сохранила тот же cref. Для новой ссылки учтён один переход и ноль регистраций; реальная регистрация клиента и оплата не выполнялись. Общая регистрация, ранее имевшаяся у тестового партнёра по другой ссылке, не приписывается этой проверке.
8. Отправлен текст, прямо помеченный как тест без реальной публикации. Демо вернуло `needs_human`; менеджер запросил исправления с пояснением, статус и оба решения видны в кабинете. Непроверенная публикация не объявлена настоящей.
9. В браузере проверены «Результаты» с отдельной новой ссылкой, недельный разбор, сохранённый диалог и исходный калькулятор. Подробности окончательной проверки и итоговые числа тестов дополняются ниже.
10. Сравнение рабочих финансовых строк с backup: Event — 3, Commission — 1, Payout — 0, CommissionAdjustment — 0, все неизменны. Реальные платежи и выплаты не запускались.

## Проблемы, исправленные во время разработки

- Прежний admin settings body отправлял внутренний `takeover`, не проходя strict-схему: теперь передаются только разрешённые поля, есть UI-тест.
- Черновик чата очищался даже при неудачной отправке: теперь сохраняется, есть UI-тест.
- После исчерпания lease retries задание могло остаться `reviewing`: теперь атомарно возвращается к `submitted`, есть интеграционный тест.
- Старая версия задания/отменённый run не может быть закрыта поздним ответом; ручные решения используют version lock.
- Административная очередь не обновлялась после worker: добавлены invalidation/refetch.
- Задания сортировались не по сроку: теперь dueAt, ближайшее отдельно на «Сегодня».
- История результатов ended program ошибочно могла блокироваться lifecycle-проверкой новых действий: read-only история доступна при сохранённом grant.
- Персональные ответы требуют отдельного external AI consent; демо не нуждается в передаче данных.
- Ключи/cookie в HTTP-логах редактируются. Сырые ответы с ошибками провайдера не возвращаются партнёру.

- API и portal TypeScript: успешно. ESLint изменённого кода: успешно. `git diff --check`: без ошибок.
- API/portal production build: успешно; запущен свежий API и проверен `/health`.
- Подготовка test DB повторена без новых миграций: успешна, данные рабочей DB не затронуты.

Неблокирующие предупреждения: текущий `pg` предупреждает о конкурентных запросах внутри одной transaction (до перехода на pg9 нужно сериализовать такие участки); существующий portal bundle включает Knex/node externalization и превышает 500 KB; React Router сообщает future flags. Это не скрывается как «все предупреждения устранены». Временная ошибка запуска Vite из корня с отсутствующим root shim исправлена запуском из `apps/portal`; окончательная сборка прошла.

## Что нельзя включать в production как «готово»

Нет live-проверенного LLM, принятой базы знаний и комплекта quality evals. Нет media uploads/OCR/публичного fetch публикаций, email/outbox, долгосрочной semantic memory и автоматической адаптации до целевого дохода. Не исправлялась финансовая политика recurring/доверенный identify без отдельного согласования. Не проводились pilot/load/mobile/security E2E в полном объёме. Наличие кода адаптера и успешных mock-тестов не заменяет эти условия.

## Следующая последовательность

1. Принять локальный пользовательский путь и UX, не изменяя исходный калькулятор.
2. Утвердить правила закрепления клиентов, recurring, возвратов и доверенной передачи событий; закрыть A04–A13 на staging.
3. Выбрать OpenRouter model ID, бюджет и политику передачи данных; сохранить подключение через админку «Подключение ИИ»; разрешить ограниченный live smoke отдельной кнопкой.
4. Наполнить/версионировать утверждённую базу Syntolk и провести сценарные evals; затем добавить собственные ссылки в контент и более развитую память.
5. Реализовать безопасные evidence uploads/fetch, email/outbox, retention; проверить отключение/отзыв согласия.
6. Последовательно завершить оставшиеся критерии, нагрузку, пилот и только потом включать реальным партнёрам.

## Дополнение: настройка OpenRouter из кабинета (12.10.2026)

Добавлен раздел «Подключение ИИ»: скрытое поле API-ключа, каталог моделей с поиском и USD-ценами, ручной model ID, сохранение/замена, явная платная проверка на синтетических данных, отдельное включение, возврат в деморежим, удаление с подтверждением. Ключ зашифрован в Config, UI/экспорт/аудит его не возвращают; проверки прав, версий и tenant scope покрыты тестами. HTTP-транзакция освобождается до внешнего вызова; поздняя проверка не подтверждает уже изменённую конфигурацию. Worker читает настройки перед обращением и не применяет поздний ответ после смены подключения. В диалог передаются текущие задания; инструкции уточнены для естественного, посильного сопровождения без обещаний заработка.

Проверки после дополнения: 72 coach/API + 25 portal + 9 financial + 29 export = **135 успешных тестов**. Публичный каталог реально доступен (262 кандидата после исключения batch-версий на момент проверки); платная генерация не запускалась. Тесты диалога — mock, не оценка реального качества конкретной модели. Сборки и TypeScript проходят; сохраняются предупреждения pg/React Router и размера портального bundle. Это дополнение не закрывает оставшиеся production-критерии из матрицы выше.
