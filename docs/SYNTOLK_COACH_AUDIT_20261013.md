# Проверка ИИ-куратора — 13 октября 2026

## Исправления

1. Включение ИИ управляется настройкой администратора. Старое поле `aiConsent` больше не блокирует создание запросов, работу очереди или ежедневные разборы. Оно сохранено только для совместимости старых анкет и резервных копий; модель его не получает.
2. Ручной способ выбора модели (`modelSelection`) хранится вместе с подключением на сервере. Пустое поле API-ключа при сохранении означает «оставить текущий ключ».
3. Повторное сохранение того же ключа и модели не сбрасывает проверку подключения, активного провайдера и текущий ответ модели. Изменение только способа выбора модели также не требует новой проверки.
4. При действительной замене ключа или ID модели нужна проверка нового подключения. Пока она не пройдена, используется демонстрационный режим. Сохранение настроек само по себе не делает платный запрос.
5. Отключить модуль можно даже с непроверенным подключением. Уже поставленные запросы не вызывают модель после отключения администратором.
6. Ежедневные разборы включаются в индивидуальных настройках партнёра администратором. Отдельная галочка партнёра для них не требуется. Анкета должна быть заполнена; пауза, тихие часы, назначенная действующая программа, дневной бюджет и режим ручного менеджера продолжают учитываться.
7. Повторная отправка сообщения с тем же идентификатором не создаёт дубликат. Подмена текста под прежним идентификатором отклоняется, в том числе в режиме ручного менеджера. Идентификатор запроса плана нельзя повторно использовать для другой недели.
8. Черновики подключения и анкеты не затираются фоновым обновлением. При конфликте версии можно явно обновить серверную версию, сохранив введённые поля. Ошибка загрузки не выдаётся за успешное обновление.
9. Смена партнёра или организации сбрасывает выбранную программу, локальный черновик и плавающее окно предыдущего владельца. Запоздалый ответ прежнего запроса не меняет новый чат.
10. Повтор после ошибки работает после перезагрузки компонента. Ошибка диалога не скрывается запросом плана. Исправлена отправка в двойном цикле эффектов React StrictMode.
11. Уточнено правило контекста: выданный сценарий не означает, что партнёр уже снял или опубликовал ролик. Выполнение определяется по присланным результатам и статусам заданий, а не по старым советам в чате.

## Как проверить самостоятельно

### Исправление неоднозначной кнопки включения OpenRouter

- Повторная диагностика показала: модуль уже включён, провайдер `openrouter`, ключ сохранён, модель `deepseek/deepseek-v4.1-flash` проверена. Неактивная кнопка «Включить» ошибочно выглядела как неисправное включение.
- В активном режиме вместо этой кнопки показываются «ИИ OpenRouter включён», сохранённая модель и путь к чату. Заголовок шага также отражает включённое состояние.
- После проверки подключения сообщение учитывает текущий режим: уже включённый ИИ не предлагают включать повторно. Если включение недоступно, рядом указана причина.
- Переключение режима ожидает обновления серверных настроек, чтобы не показывать завершение раньше обновлённого статуса.
- В браузере выполнен цикл «Вернуть демонстрационный режим» → «Включить ИИ OpenRouter» → перезагрузка. ИИ успешно включился, проверка подключения и модель сохранились. Оставлен включённый OpenRouter. Новых платных запросов к модели в этой проверке не выполнялось.
- Добавлены 6 регрессионных тестов. Итог повторного запуска: все 75 тестов интерфейса успешны; TypeScript, ESLint изменённой реализации и production build успешны. Снимок результата: `outputs/coach-openrouter-enabled-20261013.png`.

### Проверка чата и настроек

1. Открыть `/admin/coach?tab=connection`.
2. Убедиться, что показаны сохранённая модель и статус «ИИ-куратор включён». Поле ключа пустое: это нормально, сохранённый ключ не требуется вводить заново.
3. Для ручного ввода включить «Указать ID модели вручную», сохранить и перезагрузить страницу: ID и способ выбора должны остаться.
4. В разделе «Партнёры» выбрать тестового партнёра. Если показано «Сопровождение ведёт менеджер», нажать «Вернуть сопровождение куратору».
5. Открыть «Чат», написать просьбу подготовить короткий материал. Должны появиться статус обработки и настоящий ответ.
6. Для ежедневного разбора открыть «Настройки куратора», включить ежедневные разборы и сохранить час. Сервер API и фоновая очередь должны работать.

## Диагностика для разработчика

`scripts/coach-test.mts` запускает серверные регрессии в отдельной тестовой базе, а не в рабочей.

`scripts/coach-healthcheck-local.mts` проверяет локальные маршруты и выводит только техническое состояние. С флагом `--smoke` делает один диалоговый запрос через настоящую модель **только для указанного вымышленного партнёра**; такой запрос может включать несколько обращений к инструментам и оплачивается аккаунтом OpenRouter.
