# Локальный Syntolk для Windows

Запуск: ярлык **Syntolk** на рабочем столе или `.local-demo/launcher/Syntolk.exe`.

Окно содержит два независимых кабинета: «Администратор» (`http://localhost:5673/`) и «Партнёр» (`http://127.0.0.1:5673/`, Локальный партнёр Syntolk). Повторный запуск поднимает существующее окно. Закрытие окна оставляет сервисы работающими.

Запускатель проверяет Docker Engine, существующий `openpartner-postgres`, PostgreSQL 5433, API 4601, счётчик 4701 и портал 5673. Остановленные компоненты запускаются скрыто. Рабочие процессы переиспользуются; занятый другим приложением порт вызывает понятную ошибку. Отсутствующие или устаревшие сборки остановленных компонентов собираются через pnpm. База, контейнеры, миграции, исходники приложения и существующие секреты не изменяются. Агент публикаций и планировщик для новых процессов выключены.

Вход выполняется через обычные формы приложения. ADMIN_API_KEY читается из .env только в памяти. Сохранённый партнёрский вход расшифровывается AES-256-GCM. Данные поступают в окно через случайный Windows named pipe, доступный только текущему пользователю. HTTP-сервер с ключами не создаётся; ключи не передаются в URL, командной строке и журналах. Новый партнёрский ключ допускается только при отсутствии сохранённого входа или ответе 401; ошибки базы/сети не вызывают ротацию. При повреждении зашифрованного файла запуск останавливается.

Состояние, журналы сервисов и контрольные снимки: `outputs/local-launcher/`. Профиль WebView2: `.local-demo/launcher/browser-profile/`. Эти каталоги уже исключены из Git.

Сборка: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/local-launcher/build.ps1`. Используются установленный Node.js/pnpm, .NET Framework и WebView2 Runtime Windows. Официальный SDK Microsoft.Web.WebView2 1.0.4258.31 распакован в outputs/local-launcher; SHA-256 исходного NuGet: `56F7F4B8BF9AEE4B8EFEFBBDD4F67D5F74EBD1B100ED0806DA71BF76AF481AA9`.

Проверка криптографии: `node --test scripts/local-launcher/credentials.test.mjs`.

## Работа внутри Codex

Откройте проект в Codex и нажмите действие **Запустить Syntolk** в верхней панели. Оно задано в `.codex/environments/environment.toml` и вызывает `start-codex.ps1`: запускает только сервисы и готовит одноразовый локальный вход. Окно EXE при этом не открывается.

Кабинеты открываются во встроенных вкладках: `http://localhost:5673/` — администратор, `http://127.0.0.1:5673/` — партнёр. Локальная версия запоминает вход на каждом адресе отдельно. Закрытие и повторное открытие вкладок не требует повторного ввода ключа. «Выйти» удаляет сохранённый вход. Продакшен и другие адреса продолжают использовать прежнюю изоляцию по вкладкам.

Первый вход в новом профиле встроенного браузера: на странице входа выберите в поле «Файл локального входа» файл `.local-demo/browser-login/admin.ticket.json` или `partner.ticket.json`. Браузерный инструмент Codex может выполнить этот импорт сам. Файл действует 10 минут, один раз, только для своего адреса; повторное нажатие действия обновляет эти файлы. Они не содержат API-ключей. Доступ к папке разрешён только текущему пользователю Windows. Dev-маршрут отклоняет GET, чужие origin/Host, запросы не с loopback, неверные, истёкшие и повторно использованные файлы. Ключ попадает только в авторизованный локальный браузер, не в URL, чат или журналы. В production-маршрутах и production-странице входа этот импорт отсутствует.

Проверки: `node --test scripts/local-launcher/browser-login.test.mjs`, тесты `api-auth.test.ts` и `Login.test.tsx` портала. В текущей рабочей папке чата также добавлено действие с абсолютным путём к тому же `start-codex.ps1`.
